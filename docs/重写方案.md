# 解压开镜 · Rust 重写方案

> 版本：v0.1（方案定稿 + P0/P1 已落地）
> 原项目：`E:\code\解压开镜`（Python 3.10 + PySide6，v0.12.2，13,998 行）
> 新项目：`E:\code\Rust-解压开镜`

## 1. 为什么重写：先认清 44 MB 是怎么来的

原版单文件 EXE 实测 **44.37 MB**，拆开看：

| 组成 | 体积 | 占比 |
| --- | --- | --- |
| Qt6Core.dll | 10.0 MB | 23% |
| Qt6Gui.dll | 9.2 MB | 21% |
| Qt6Widgets.dll | 6.2 MB | 14% |
| python310.dll | 4.3 MB | 10% |
| PySide6 绑定 + Qt 插件（platforms/imageformats/tls/…） | ~10 MB | 23% |
| **业务代码（全部 .py 压进 PYZ）** | **1.2 MB** | **3%** |

结论：体积问题**不是代码问题，是 GUI 运行时问题**。PyInstaller 再怎么 exclude，
Qt Core/Gui/Widgets 这三件套是省不掉的，天花板在 30 MB 以上。

因此重写目标不是"把 Python 换成 Rust"，而是"**把 Qt + CPython 换成 Rust + 系统 WebView2**"。

## 2. 技术选型

| 方案 | 体积（估算） | UI 工作量 | 玻璃效果 | 结论 |
| --- | --- | --- | --- | --- |
| 继续 Python + Qt（瘦身） | 34–36 MB（UPX 后 20 MB，有加载风险） | 0 | 完美 | 天花板太高，放弃 |
| Rust + egui | 5–8 MB | 高（控件生态弱） | 需手调 DWM Acrylic | 备选 |
| **Rust + Tauri v2** | **3–5 MB** | 中（HTML/CSS/JS） | CSS 完整还原 | **选定** |
| Rust + Slint | 8–12 MB | 中 | 一般 | 放弃 |

Tauri 的代价只有一个：依赖系统 WebView2 运行时。本机实测已装 **157.0.4341.60**，
Win11 全系自带，Win10 自 21H2 起随 Edge 预装；缺失时安装包引导一次即可。

同时 Rust 版在别处也有收益，这些是体积之外的真收益：

- 启动：Qt 冷启动约 0.6–1.2 s，Tauri 窗口通常在 0.2 s 内出界面
- 内存：空载 PySide6 约 120 MB，Tauri 约 40–60 MB
- 右键小窗：每次调用不再拉起整个 Qt 运行时，弹窗延迟显著下降
- 杀软误报：PyInstaller onefile 是重点误报对象，自编译 Rust 二进制基本没有
- 分发：3 MB 的绿色版，丢进网盘/U 盘即可

## 3. 目录结构

```
Rust-解压开镜/
├── Cargo.toml                  # workspace
├── crates/
│   ├── jieya-core/             # 引擎（零 GUI 依赖，可单测、可被 GUI/CLI 共用）
│   │   └── src/
│   │       ├── config.rs       <- core/config.py
│   │       ├── sevenzip.rs     <- core/sevenzip.py
│   │       ├── detect.rs       <- core/archive_detect.py
│   │       ├── probe.rs        <- core/probe.py
│   │       ├── output.rs       <- core/output_plan.py
│   │       ├── pipeline.rs     <- core/pipeline.py
│   │       ├── walk.rs         <- core/filewalk.py
│   │       ├── models.rs       <- core/models.py
│   │       ├── fmt.rs          <- core/formatting.py
│   │       └── error.rs        <- 新增（thiserror 统一错误）
│   └── jieya-cli/              # 命令行入口（bin: jieya）
├── app/                        # Tauri 外壳（P4 接入）
├── ui/                         # 静态前端 HTML/CSS/JS（P4）
└── docs/                       # 本方案
```

`jieya-core` 的原则与原版一致：**零 GUI 依赖**。GUI 和 CLI 都只是它的调用方，
这样绝大部分行为可以脱离界面做单元/集成测试。

## 5. 分期与验收

| 阶段 | 内容 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| **P0** | 工具链、workspace、体积基线 | release 构建通过，CLI 体积 < 5 MB | ✅ |
| **P1** | 无密码引擎：探测→落点→解压→BFS 内层 | 多层 zip/7z 递归解压产物结构与原版一致 | ✅ |
| **P2** | 密码系统：候选、库、AES、ZipCrypto 预筛 | 加密包自动命中；AES 包不再走 7z 假错路径 | ✅ |
| **P2.5** | 云端密码库 | MD5 查询 + 后台线程插队 | ⬜ |
| **P3** | 名字修复、内嵌包、任务持久化、暂存清理 | 日文乱码包整树修复、视频内嵌 ZIP 可解、残留可安全回收 | ✅ |
| **P3.5** | 分卷归并（缺首卷告警）、vault 加密导出/导入 | 跨目录分卷能归并解出；`.vault` 与 Python 版双向互通；错口令被拒 | ✅ |
| **P4** | Tauri GUI：主窗/设置/密码库/清理 | 主要操作可在界面完成 | ✅ |
| **P5** | 右键菜单、便携版打包 | 双击即用、菜单安装/卸载、`cargo test` 全绿 | ✅ |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `name_repair` 启发式难对齐 | 乱码修不好或把好名字改坏 | 先把原版 `tests/` 里编码样例搬成 Rust 测试；判定函数逐条对照移植 |
| WinZip AES 细节 | 加密 ZIP 解不开 | 复用原版 `docs/password-speed.md` 的实测包做对照；AES-CTR + HMAC-SHA1 + PBKDF2 用成熟 crate |
| Tauri 玻璃效果 | 观感不如 Qt | 透明窗口 + DWM Acrylic；先在 P4 做一个样板窗验证再铺开 |
| WebView2 缺失 | 老 Win10 打不开 | 安装器检测并引导；同时保留 CLI 纯绿色可用 |
| 7z 仍是外部依赖 | 需用户装 7-Zip | 与原版一致；后续可选内置 `7zr.exe`（约 600 KB） |

## 7. 兼容性

- **数据目录不变**：`%LOCALAPPDATA%\解压开镜`（config.json、data/vault.db、.workspace）
- **密码库零迁移**：SQLite 原表 `passwords(id, password, source, hit_count, created_at, last_hit_at)` 直接由 rusqlite 打开
- **与原版可共存**：新 EXE 名 `jieya.exe` / `解压开镜.exe`，右键菜单项互不覆盖（P5 处理）
